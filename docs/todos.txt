TODOS for v0.1.3

This version is mostly backend focused.

1. tier 3 first (small, mechanical, gets the safety net up early):
std::optional for the 13 genuine "not found" returns in EffectRegistry & friends.
NOT for the ~49 observer pointers like LogicalDevice* -- null is never legal there,
so optional would be noise pretending to be safety.

2. tier 2: Vulkan handle ownership. bigger than it looks:
src/render/* are thin factories that call through pLogicalDevice->vkd.CreateImage(...)
and hand raw VkImage / VkDeviceMemory back to callers who own the lifetime informally.
only 4 destroy call sites remain, so this is not a mechanical sweep, it is designing
ownership for handle types that currently have none.
the hard part: Vulkan forbids destroying a resource the GPU is still using, and most
of these are freed after a vkQueueWaitIdle rather than at end of scope. a scope-bound
deleter would fire too early. needs an owner-aware handle plus a deferred-destruction
queue, agreed on before any code is written.

3. KeyUniform is a stub that writes a hardcoded VkFalse with a TODO. any effect using
source = "key" compiles, shows up in the UI, and silently does nothing forever.
that is worse than a crash: no error, no warning, just a dead effect. either implement
real key state tracking or deny keyed effects honestly, like DepthAlpha.fx.

3.5 qUINT_mxao.fx sometimes leaves a ghost "MXAO" entry in the UI that can never
be enabled. FIX FIRST, before tier 2.
cause is a key collision, not the shader. qUINT_mxao.fx declares one technique
named MXAO, and the .ini save path writes entries as technique@filename
(imgui_overlay.cc:724), but a bare "MXAO" ended up in the VKIntoxEffects list
at configs/vkcube.conf:83:
    effects = DisplayDepth:qUINT_ssr:qUINT_mxao.2:MXAO
those keys are INSTANCE names, and "MXAO" is never a registered instance, so it
resolves to nothing: displayable, never enableable, never removable.
the .ini files are all correct (MXAO@qUINT_mxao.fx); only the config's effect
list is wrong. likely a legacy write path that emitted the technique name
instead of the instance name, so find every writer of VKIntoxEffects and make
it agree on the format rather than patching the one bad line. also worth
having the loader drop effect-list entries that name no known instance, so a
corrupt list degrades instead of ghosting.

4. split the monoliths, AFTER ownership settles so the new files get clean seams:
vkintox.cc 6759 lines, imgui_overlay.cc 1418, config_serializer.cc 1309,
command_buffer.cc 873. also do this on main at some point: main's smoke test has no
depth effect seeded, so it tests the pass-through path rather than the resolve path.

5. global audit for memory leaks, resource leaks, and bugs. -Wall is already on and
the build is clean, so this wants a real pass, not a checkbox.

6. port built-in effects into ReShade .fx files ... or stop using them? Remove them
